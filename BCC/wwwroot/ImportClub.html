Club Import code flow

BCCPunte · Admin → Import Club · /admin/club-import

There is no ClubImport service class. Club import is the club-import admin route: UI in Admin.razor, logic in the ClubImport region of Admin.razor.cs, with monthly/date/promotion work in DataService. Images Process (images-import) is a separate path.

Branch A — last import month is September

No CSV. YearEnd() → OctoberMonth():

  1. Reload dates (ds.LastDates()).
  2. Run promotions (ds.Promotion_Due()).
  3. Advance Datum.lastImport to lastDateClubImported + 1 month, or to the latest Monthly date if salon import already created October rows.

Shared CSV parse

Both importers:

  1. Import(filename) → ds.LastDates() then find *{fn}* under Import.
  2. TextFieldParserInitialize — first line lowercased, split on commas into Headers.
  3. SetScoreIndices() / SetResultIndices() — column indexes from ScoreHeaders / ResultHeaders.
  4. HeadersCheckScores — required columns, then a peek at the first data row for a 7-digit IntRef. If a Photo with that IntRef already exists in lastDateClubImported.Year, this is treated as a re-import.

Required Scoresheet headers (ScoreHeaders): category, memberid, lastname, firstname, club star rating, title, internal reference, email, honours, scoretotal, awards.

Required Results headers (ResultHeaders): category name, award id, event photo id, photo title, lastname, firstname, club star rating, honours.

BCC/Adm/Club/Admin.razor.cs:332–335

string ln = p.PeekChars(400).Replace("\"", string.Empty).Replace(",", ";");
int ir = int.Parse(Regex.Match(ln, @";(\d{7});").Groups[1].Value);
return await repo.AnyAsync<Photo>(x => x.IntRef == ir && x.Monthly.Date.Year == gData.lastDateClubImported.Year);

Re-import behaviour is not the same for both files:

  • Scoresheet already in DB → UpdateScores: fill Photo.Score on existing rows for Monthly.Date >= lastDateClubImported. Throws if the first photo already has Score > 0.
  • Results already in DB → message "Already Imported Scoresheet into DB" and stop. No award merge.

So a second pass that adds scores is Scoresheet-after-Results. Results-after-Scoresheet is rejected.

New-import path (Scoresheet)

BCC/Adm/Club/Admin.razor.cs:388–426 — ImportScores(string filename)

  1. processLineScores — one Photo per CSV row:
    • Category, PVID (memberid), honours, email, title, IntRef, Score.
    • Club_Rating: Golden Honours→6, Galaxy→7, else int.Parse.
    • Star_Group: 1–2→1, 3→2, 4–5→3, else 4.
    • Awards string: ~\w+~ sets both Winner flags; a lone ~ with IC is club winner, otherwise overall winner.
    • Award = first word character (C/G/S/B).
    • Category "S" stays "S"; otherwise "N"/"P" plus star group (N3, P1, …).
  2. Group by PVID. For each member:
    • GetMasterRow — lookup Master.IdVault == PVID, or Master.Name if PVID is null. Missing master → confirm dialog (State.ShowConfirmAsync → MessageBox.razor). Yes → AddNewMaster (split name on last space, repo.AddSaveAsync).
    • ds.GetLastMonthly(master) — attach MonthlyID.
  3. PhotoQuantity — per MonthlyID: max 3 non-S, max 2 S. Over limit → inline chooser on Admin.razor (tick to delete). Cancel returns an empty list and still continues the later steps.
  4. Save photos via RepoScope.AddRange + SaveChangesDetachAsync.
  5. Shared close-out: MonthlyUpdate → MonthlyCompute → ds.Promotion_Due → DatesStoreInDb → ds.CleanImportDirectory.

Success message: "Successfully Imported {count} Records".

New-import path (Results)

Same shape, with these differences:

  • processLineResults — no PVID, no score. Award "com" → "C". Lastname "DeBeer" → "De Beer". Category is first character of category name.
  • After parse, collapse duplicate IntRefs: keep the row whose Award length is 1; set Club_Winner if any sibling is "CW"; set Winner if any sibling is longer than 1 and not "CW". Then drop every row with Award.Length != 1.
  • Group by Name, not PVID (Results CSV has no member id).
  • Same quantity check, save, and close-out. Success message is only added on the Scoresheet path.

Monthly lifecycle (DataService.GetLastMonthly)

BCC/Services/DataService.cs:39–45

public async Task<Monthly> GetLastMonthly(Master master)
{
    Monthly monthlyLast = await repo.monthlyLastNTAsync(x => x.MasterID == master.ID);
    monthlyLast = monthlyLast ?? await MonthlyNew(master);
    monthlyLast = (monthlyLast.Date <= gData.lastDateClubImported) ? await MonthlyCopy(master, monthlyLast) : monthlyLast;
    await repo.UpdateSaveDetachAsync(monthlyLast);
    return monthlyLast;
}
  • No history → MonthlyNew dated lastDateClubImported + 1 month.
  • Latest monthly is already on or before last club import → MonthlyCopy: new monthly for next month, copy year accumulators (Mg/Gg/…, Pp, Py, VOy, Saly). If the new date is November, or the old monthly is before lastDateClubYear, year fields are cleared.
  • Latest monthly is already after last import (typical after salon import created next month) → reuse that row. Club photos attach to it instead of creating another month.

Club fiscal year starts 1 November (Extensions.toClubDate).

Points and promotion after save

MonthlyUpdate walks photos for the latest monthly date:

  • Category not S and not PH: C→Mm, G→Gm, S→Sm, B→Bm (counts).
  • Category S: C→VOm+5, G+3, S+2, B+1.

MonthlyCompute turns those counts into points (AddNull treats null as 0, stores null if the sum is 0):

This monthClub points PmGold medals GMp path
Mm (COM)×5Mg += Mm
Gm (Gold)×3Gg += Gm
Sm (Silver)×2Sg += Sm
Bm (Bronze)×1Bg += Bm

Then GMp = Mg+Gg, Pp += Pm, GMy += Mm+Gm, Py += Pm, VOy += VOm.

Promotion_Due flags Monthly.Promotion from these thresholds, then Promote bumps RatingID on Master and Monthly only if Promotion == true and Pp != Pm (a member whose only points are this month is not promoted yet). Accumulators GMp, Pp, Mg, Gg, Sg, Bg are cleared on promote.

RatingIDCriteria
1GMp >= 4, Pp >= 20
2GMp >= 6, Pp >= 35
3GMp >= 8, Pp >= 50, Salp >= 18
4GMp >= 12, Pp >= 80, Salp >= 50
5Pp >= 150, Salp >= 200, Title == "APSSA"
6Pp >= 150, Salp >= 400, Title == "FPSSA"

Date stamp after a successful CSV import

BCC/Adm/Club/Admin.razor.cs:279–291

public async Task DatesStoreInDb()
{
    Datum lastImport = await repo.Datum(x => x.ID == "lastImport");
    var latestdate = await repo.monthlyLastDateAsync();
    lastImport.Date = latestdate;
    gData.lastDateClubImported = lastImport.Date;
    if (lastImport.Date.Month == 11)
    {
        Datum newyear = await repo.Datum(x => x.ID == "clubYearStart");
        newyear.Date = lastImport.Date;
        gData.lastDateClubYear = newyear.Date;
    }
    await repo.UpdateSaveDetachAsync(lastImport);

lastImport becomes the max Monthly date. Crossing into November also updates clubYearStart. Staging CSVs are then deleted by ds.CleanImportDirectory().

Photo fields used only during import

PVID, Name, Email, Honours, and Flag on Photo are [NotMapped] (BCC/Models/Photo.cs). They exist for this import (member lookup, chooser ticks), not as Photo table columns. Persisted fields include MonthlyID, Club_Rating, Star_Group, Category, Title, IntRef, Score, Award, Winner, Club_Winner.

What this path does not do

  • It does not unzip or resize competition images. That is admin/images-import → ImagesProcessAsync.
  • It does not import salon CSVs. That is SalonImport from salon admin.
  • Helpie.html section 18.2 describes this flow but is stale in places (line numbers; PhotoQuantity is an interactive chooser, not “keep first 3/2”; OctoberMonth does not call DatesStoreInDb; Results-after-Scoresheet is rejected by HeadersCheckScores).
