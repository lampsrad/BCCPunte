1. Project Overview & Architecture

BCCPunte is a full-featured Blazor Server application that manages the entire competition lifecycle of the Bloemfontein Camera Club (BCC). It handles monthly club competitions (Pictorial, Nature, Set Subject, Cell-Phone), star-level promotions, Golden Honours / Galaxy tracking, PSSA national & international salon results, member master data, photo asset pipelines, and public website content publishing.

High-Level Architecture

  • UI: Blazor Server (real-time SignalR updates). No MVVM/ViewModel layer — components inject Repo + State directly and perform data binding inline.
  • State: Singleton event bus (State.cs) for cross-component communication (progress, messages, date changes, file dialogs).
  • Data: Repository pattern with generic EF helpers. All EF access funnels through Repo. RepoScope provides transactional units of work with eager includes.
  • Business Logic: Concentrated in DataService (promotion engine, monthly record lifecycle) and SalonImport (PSSA CSV parsing + point aggregation). The massive Admin.razor.cs contains the club data import engine and the entire image processing pipeline.
  • EF Core: Minimal BKKEntities DbContext (no Fluent config). Relationships via navigation properties + conventions. Heavy use of AsNoTracking() + manual ChangeTracker.Clear() for performance.
Fiscal Year Rule: Club year starts 1 November. Almost every date-sensitive calculation (year accumulators Py/VOy/Saly, promotion windows, monthly copy logic) uses the custom .toClubDate() and .toDateFirstDay() extensions.

9. Business Service: DataService.cs

Monthly Lifecycle Core

public async Task<Monthly> GetLastMonthly(Master master)
{
    Monthly last = await repo.monthlyLastNTAsync(x => x.MasterID == master.ID);
    last = last ?? await MonthlyNew(master);
    last = (last.Date <= gData.lastDateClubImported) 
        ? await MonthlyCopy(master, last) 
        : last;
    await repo.UpdateSaveDetachAsync(last);
    return last;
}

MonthlyCopy duplicates year accumulators (GMy, Py, VOy, Saly) and clears them when crossing the November boundary or when the previous record is before club year start.

10. Business Service: SalonImport.cs (PSSA Import)

Full pipeline for national/international salon result CSVs.

  1. Locates *{salonname}*.csv in ImportDirectory
  2. TextFieldParser with smart delimiter detection (; vs ,) and quote handling
  3. Filters rows where ClubName contains "Bloemfontein"
  4. Regex on AwardDescription column detects: acceptances, COMs, special medals (FIAP, PSSA, Club)
  5. Aggregates per photographer (multiple images per salon entry)
  6. Points = Acceptances + (Com × 2); ×2 again if SalonMaster.International
  7. Calls Ds.GetLastMonthly to ensure a Monthly record exists for the salon date
  8. Updates Salon + Monthly.Salm / Salp / Saly
  9. Invokes Ds.Promotion_Due()
The regex patterns for awards are quite loose ("acc", "com", "cert", "fiap", "pssa", "club") and rely on .toCap() for display.

18. Image Processing Pipeline — Detailed Flow

Triggered from Admin page "Images Process" button. Uses IProgress<ProgressInfo> for live UI updates via State.UpdateProgress.

Key transformations:

  • Original filenames from camera or download service are ignored.
  • Matching is done purely on numeric IntRef (PVID) extracted during CSV import.
  • High IntRef numbers (>10M) are treated as "Censored" and mapped to images/Censored.jpg.
  • Final published images live under /photos/2025-11/12345.jpg (served from physical gData.photosLocal via static file middleware).

18.1 Admin: Images Process – Complete Step-by-Step Workflow

This is one of the most important (and longest-running) operations in the entire application. It is triggered when an administrator clicks Images Process in the Admin dropdown menu. It transforms raw competition photos received from PhotoVault into web-ready images and publishes them both locally and to the live production website.

How to Trigger It

  1. Go to the top menu → Admin → Images Process
  2. The browser navigates to /admin/images-import
  3. OnParametersSetAsync() in Admin.razor.cs:221 immediately calls ImagesProcessAsync()
  4. A file upload dialog appears asking for "ZIPPED PHOTOS" from PhotoVault

Prerequisites (Very Important)

  • The monthly competition data (scores + results CSVs) must already have been imported for the target month. This creates the Photo records containing the 7-digit IntRef (PVID) numbers that will be used for matching.
  • You must have received one or more ZIP files from PhotoVault containing the high-resolution images for that month.
  • The ZIP filenames usually contain the month (e.g. something like "BCC 2025-11.zip").

The Complete 7-Stage Process

Stage 1: File Selection (FileUpload)

Calls state.ShowFileUpload("ZIPPED PHOTOS", "Upload Zipped Photos from PhotoVault", gData.ImportDirectory).

The selected ZIP file(s) are saved into wwwroot\Import\. The variable Filename is set to the base name chosen in the dialog (this becomes the month folder name, e.g. "2025-11" or "2026-03").

Stage 2: Unzipping (PhotosLocalUnzipAsync)

Location: Admin.razor.cs:761

  • Finds every *.zip file currently in gData.ImportDirectory
  • Creates the destination folder: D:\BKK\Inbox\Club\Photos\{Filename}\ (example: D:\BKK\Inbox\Club\Photos\2026-03\)
  • Extracts the contents of every ZIP into that folder using ZipFile.ExtractToDirectory(..., overwriteFiles: true)
  • Live progress is reported for each ZIP file ("Extracting BCC-2026-03.zip (2/3)...")
After this stage you will see a folder full of the original high-resolution JPGs with their original PhotoVault filenames (often containing the 7-digit ID somewhere in the name).

Stage 3: Copy & Rename to Temp (PhotosCopyRenameAsync)

Location: Admin.razor.cs:802

This is the critical matching step.

  • Scans D:\BKK\Inbox\Club\Photos\{Filename}\ for all *.jpg
  • For each file, runs regex \d{7} against the original filename to extract the 7-digit internal reference number (this must match Photo.IntRef from the earlier CSV import)
  • If no 7-digit number is found → the file is skipped and logged in the Errors list
  • Valid files are copied (with overwrite) into a new subfolder: ...\{Filename}\Temp\ and renamed to simply #######.jpg (e.g. 1234567.jpg)
  • Uses parallel Task.Run for performance
If many files are skipped here, it almost always means the monthly Photo records were not yet imported, or the ZIPs contain images from a different month.

Stage 4: Generate Web Previews (PhotosGeneratePreviewsAsync + GenerateImagesAsync)

Location: Admin.razor.cs:861 and 689

  • Source: ...\{Filename}\Temp\
  • Destination: D:\BKK\Inbox\Club\Photos\WEB\
  • Uses SixLabors.ImageSharp to process every image:
using (var image = await Image.LoadAsync(source))
{
    image.Mutate(x => x.Resize(new ResizeOptions
    {
        Mode = ResizeMode.Max,
        Size = new Size(1365, 768)
    }));
    await image.SaveAsync(destination);
}
  • Target size is hardcoded to 1365 × 768 pixels
  • ResizeMode.Max = maintains aspect ratio, fits inside the box
  • Extremely parallel: uses Environment.ProcessorCount (usually 8–16 threads)
  • Progress is reported after every single image

Stage 5: Zipping + Distribution (PhotosZipAsync)

Location: Admin.razor.cs:905

This stage does several important things at once:

  1. Creates a ZIP of everything in D:\BKK\Inbox\Club\Photos\WEB\ → C:\Users\lammie\Downloads\BKK\ZippedExport\BKK-{Filename}.zip
  2. Copies every generated preview into the running app's own static folder:
    wwwroot\ClubPhotos\{Filename}\ (so the local site immediately sees the new photos)
  3. Also copies the same files to the "source of truth" local website folder:
    D:\VS\VS Active\BCCBlazor\BCC\wwwroot\ClubPhotos\{Filename}\ (used when publishing the whole site)
  4. Deletes the files from the temporary WEB\ folder after copying

Stage 6: Authentication (Login)

Location: Admin.razor.cs:742

Before uploading, the app authenticates against the live site:

POST https://bkk.co.za/Auth/login
Body: { "username": "...", "password": "..." }

Credentials come from appsettings.json → "Auth" section. Returns a JWT Bearer token.

Stage 7: Upload to Production (UploadToHosting)

Location: Admin.razor.cs:953

  • Only accepts .zip files
  • Hard limit: 120 MB maximum
  • Timeout: 15 minutes
  • Uses MultipartFormDataContent
  • Endpoint: POST https://bkk.co.za/FU/zip with Authorization: Bearer {token}
  • The production server receives the zip and is responsible for extracting it into its own wwwroot/ClubPhotos/{month}/ folder

Final State After Successful Run

  • Original high-res photos remain in D:\BKK\Inbox\Club\Photos\{Filename}\
  • Web-optimized 1365×768 images exist in:
    • Local running app: wwwroot/ClubPhotos/{Filename}/
    • Source website folder (for future publishes)
    • Live production site (after the server extracts the uploaded zip)
  • A backup zip is left in your Downloads folder
  • All messages from each stage are shown on the Admin page

Important Side Effects

  • Every successful Import Club run ends with Promotion_Due() being called. This can promote members and update their star level in real time.
  • The lastImport date in the Datum table is advanced.
  • All processed files are deleted from wwwroot/Import/ by CleanImportDirectory().
  • Extensive use of RepoScope + SaveChangesDetachAsync() to keep EF change tracker clean during long imports.

Typical User Workflow

  1. Receive Scoresheet.csv from club scoring system → place in Import folder or use dialog
  2. Click Admin → Import Club → select the Scoresheet file
  3. System creates/updates Masters, Monthlies, and Photo records with scores
  4. Later, after judging: receive Results.csv → Import Club again with Results file
  5. Awards, Winners, and final points are applied. Promotions are recalculated.
The order matters: Scoresheet (scores) should normally come before Results (awards). Importing Results first can cause issues because MonthlyUpdate and MonthlyCompute rely on having the base Photo records already present.

21. Configuration, Secrets & Environment Handling

Three connection string templates in appsettings.json. Local uses placeholder replacement in DbContextFactory:

"Local": "Server =[ServerName]; Database= [DatabaseName]; ..."

Runtime switch between "Local" and "Abshost" is possible via the DB menu item (updates gData.connectionKey and HitCounter for auditing).

22. Development Notes, Risks & Observations

Strengths

  • Extremely consistent "everything through Repo" discipline.
  • Excellent handling of the awkward Nov–Oct fiscal year in dozens of places via a single extension method.
  • Real-time progress for long-running image jobs is well implemented.
  • Self-contained deployment + auto-launch Chrome makes it easy for club volunteers.

Risks & Technical Debt

  • ~950 lines of business logic in a single code-behind file (Admin.razor.cs).
  • Hardcoded paths and passwords in multiple places (gData + appsettings + occasional strings).
  • No automated tests whatsoever (explicitly stated in CLAUDE.md).
  • Heavy use of ChangeTracker.Clear() and AsNoTracking() indicates tracking-related pain in the past.
  • Commented-out email and API service code still present.
  • Promotion rules and star thresholds are magic numbers with no UI or data-driven configuration.
  • Regex-based award detection in salon import is fragile.

Interesting Implementation Details

  • IntRef > 10 000 000 is the "censored" sentinel value.
  • Many point columns (VOm, Mm, etc.) are deliberately left nullable so that "no data yet" is distinguishable from zero.
  • The same Monthly record can be updated multiple times during a single import (scores → results → images → salons).
